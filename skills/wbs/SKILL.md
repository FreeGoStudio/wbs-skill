# WBS 任务拆分

依据用户原始需求和后续确认，生成可独立阅读、分派和验收的任务。默认中文。读取目标项目适用的 AGENTS.md、现有清单及用户指定资料；沿用其目录、编号和已确认规则，不将本技能当作新增业务需求或开发授权。

## 选择工作方式

- 新建或补充任务：读取 [任务生成模板](references/task-template.md)，按实际目标选用单任务或工作包结构。模板是写法参考，不能预设任务数量。
- 修改已有任务、迁移归属、维护预算或产品任务：另读 [已有规划维护](references/maintenance.md) 中相关章节。新任务规则不自动触发旧任务转换、预算重算或评审测试任务删除。
- 用户只要求分析或聊天草稿时直接回答；要求保存时复用项目现有文档与导航。不要为使用技能创建 Goal、聊天或开发任务。

## 拆分流程

1. **核对需求及已有能力。** 回到原始要求及最新确认，检查现有任务、接口资料或相关实现，区分复用能力、本次增量和真实未知。可直接查明的事实先查；需要调查的技术未知形成具体核查任务，交付下游需要的结论或契约。未确认业务规则写明影响，不代替用户裁定。
2. **确定业务目标与归属。** 单一实施目标且可独立交付时直接使用主编号。多个可独立交付结果才拆为“工作包→实施任务”。父包按业务目标确定，各端以责任角色区分；同一独立方案的新增子任务统一归属，复用外部能力用依赖关联。
3. **写出任务卡。** 保留编号、具体名称、类型、责任角色、实施内容与产出、依赖、完成标准；仅子任务填写父任务。核查写问题和产出，后端写接口业务行为，页面写入口、位置、准确文案和关键状态。保留金额口径、默认值、生效规则和关键异常，避免重复叠加目标、业务表和开发说明。
4. **检查依赖和集成。** 引用真实编号及所需产出，分清开发前置与接口联调；共同验收不构成互为前置。拆分不得破坏事务、资金和数据一致性，需要共同启用的能力明确集成验收点。
5. **同步与验证。** 核对编号唯一、父包覆盖、依赖有效且无环，单任务只计一次。保存时同步受影响的导航、简版、批次和迁移映射；仅涉及既有预算时核对工时汇总。运行项目已有的只读文档检查和 Git 差异格式检查，检查 UTF-8 无 BOM、LF、表格与本地链接；不要假设每个项目都有同名检查脚本。

## 输出约束

- 每项围绕单一目标和可检查结果，不以建类、加字段等技术动作凑任务，不用“完善功能”“联调所有问题”吸收无限范围。
- 新任务不预填工时、预算或完成证据字段，不自动拆常规评审、测试验收或产品任务。工时由需求评审会评估，整体由产品验收；这些通用流程不复制进任务正文。
- 不按预设小时数或固定端数拆分；已有能力明确时不机械增加核查任务。规划阶段只写角色，不分配个人占位。
- 未变化的样式与交互写“沿用现有实现”；不补常规环境、账号、权限清单或泛化风险提醒。具体阻塞和特殊限制按需保留。
- 主任务概述只说明业务目的和改动，管理安排放规划入口；子任务自身可读。截图就地展示并有统一图号，不编造截图、路径或接口。
- 新发现的关联缺陷不自动扩入当前范围。用户已授权纳入规划时，登记为具体缺陷任务并关联父包，工时留待评审；否则只报告与本次任务的关系。
- 保持用户已确认的范围；不因缺环境或外部契约新增外围开发。最终区分规划文档完成、自动检查结果和仍需确认的具体条件，不声称业务实现或验收已完成。

Git 提交遵循用户和目标项目的授权；技能本身不授权提交或推送。需要提交时，主题和正文使用中文，技术标识及类型前缀可保留英文。
