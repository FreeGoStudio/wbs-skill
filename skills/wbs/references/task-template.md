# 任务生成模板

## 使用与生成规则

生成新任务时，先确定业务范围和主编号，再判断是否需要拆分。只有一个实施目标、可独立交付时，使用“单任务骨架”；确有多个可独立交付的实施任务时，才使用“拆分任务的主任务骨架”，按实际工作选用子任务写法。尖括号中的内容是填写占位符；生成结果删除填写提示和不适用段落，本节不复制到任务正文。

- 主任务讲清业务目的、整体改动和产品验收结果；子任务写清各自要完成的具体工作。
- 子任务单独分派后应能读懂，不依赖主任务补全入口、准确文案、显示条件或数据口径。跨任务接口契约可以引用具体产出。
- 内容长度随复杂度变化。简单改动用短段落和少量条目；只有字段或状态确实需要对照时才用表格，不把普通表单交互展开成状态大全。
- 页面任务说明改动位置、名称、关键状态及相关截图；未改动的布局、样式和通用交互用“沿用现有实现”概括。核查和后端任务无需复制页面设计。
- 保留影响实现的默认值、准确文案、金额口径、生效规则及关键异常。完成标准简短、可检查，不再重写一遍开发说明。
- 仅引用用户提供或已核实的接口、字段、文件及能力。技术未知需要调查时，建立具体核查任务，以结论和契约作为后续输入，不将尚不存在的核查记录要求为前置资料，不预设调查时限。
- 按实际工作及可独立交付的结果拆分，不固定为核查、后端、POS、Web 四项；契约已明确时不机械增加核查任务。核查、后端、页面三种写法按需选用，其他任务按相同原则描述。
- 单任务直接使用主编号，不创建子编号、父任务字段或子任务一览；拆分后的子任务编号采用“父任务编号-两位流水号”，不复用已取消编号。按责任角色描述，不预分配个人。
- 开发前置写“先完成什么才能开发”，接口联调写“需要什么接口可用”。共同参与整体验收不表示双方互为开发前置；无依赖写“无”。
- 阶段和就绪状态只在有明确安排或阻塞时填写。不列预计工时、预算汇总、完成证据字段，也不列源码、环境、账号、权限等常规条件；仅在真实特殊限制影响实施时具体说明。
- 工时由需求评审会全员评估，评审在会上完成，整体结果由产品验收，不自动生成独立评审或验收任务。
- 不把编辑过程、格式评阅、历史预算解释、泛化风险提醒写进任务正文。业务未决问题只列影响本次实施的具体问题，不附通用“遇到问题如何汇报”的说明。
- 任务概述只写业务目的、使用场景和整体改动，不自动添加管理说明段落。主编号、子任务数量和归属由标题、子任务一览及父任务字段表达，不再用段落复述；不写“本文件是完整任务卡来源”等清单用途或权威性声明。
- 工时由谁评估、评审如何组织、由谁验收等通用流程保留在本模板和仓库约定中，不复制到生成的任务正文。整体完成标准直接列可检查的业务结果。
- 独立评估、独立排期、排除某批次等安排在规划或批次入口维护，不自动拼入任务概述。仅当具体安排影响实施或形成真实阻塞时，在对应阶段、依赖或启用条件中简短说明；不重复堆叠管理声明。

### 先确定主任务与归属

- 主任务就是业务工作包，必须有唯一编号、明确的业务范围和整体完成标准。子任务统一使用该主任务编号作为前缀，任务卡中的“父任务”与此前缀一致。
- 用户要求把一个完整业务方案作为独立任务管理时，为该方案建立独立工作包及主任务编号，按实际交付需要决定是否拆分子任务；不能仅新增独立文件，却把实施任务继续分挂在原来的多个父包下。
- 父包按业务目标确定，不按后端、POS、Web等责任端确定。同一方案中的核查、后端、POS及页面工作，只要共同交付该业务目标，就归属同一主任务，通过“责任角色”区分实施方，不增设端级父任务。
- 对已有工作包范围内的局部补充，沿用该父包；仅要求独立文件、单独展示或排除某个批次，不自动等同于新建工作包。依据用户已确认的业务范围和管理意图判断，不因文件位置改变父子关系。
- 新主任务编号先核对当前清单及项目已有编号与迁移索引（如有），沿用仓库编号约定，避开已使用、取消和迁移保留的编号；确定主编号后，子任务使用“主编号-01、主编号-02”等两位流水号。
- 复用其他工作包的既有能力时，引用对应任务编号及所需产出作为跨包依赖，不复制活动任务，也不因此改变本方案子任务的父包。
- 用户已要求将既有任务改为独立工作包时，为该包分配主编号及对应子编号；原编号保留迁移映射与跳转，不再计为活动任务，不复用。同步任务卡、依赖、简版、编号索引、导航及受影响汇总；不以“保留稳定编号”为由维持错误归属，也不据此批量重编其他任务。
- 父子归属与交付批次分别管理。独立工作包不自动进入现有批次；明确排除的批次不得把它列为交付内容或反向设为既有任务的开发前置。

### 截图与引用

有截图时，使用“图 1：页面名称（状态）”作为图片名称和图注。正文引用具体图号及图名，不使用“目标效果参考图”等泛称；同一主任务内不同截图顺序编号，同图重复展示沿用同一编号。页面子任务就地展示相关截图，不能只让开发者返回主任务找图。

图片用真实相对路径，存入项目约定的资源目录；无截图则省略图片段落，不生成占位图片链接。截图与文字有冲突时只记录具体差异，不从图中自行扩展范围。

```markdown
![图 1：<页面名称（状态）>](<真实图片相对路径>)

*图 1：<页面名称（状态）>*
```

## 单任务骨架

只有一个实施目标、可独立交付的任务直接使用主编号。实施内容按核查、后端或页面工作写清必要业务行为，不复制主任务与子任务两套描述，不添加子任务一览或父任务字段。单任务按一项实施任务统计，工作包层不重复计数。

```markdown
# <主编号> <任务名称>

- 编号：<主编号>。
- 类型：<实际类型>；责任角色：<角色>。

## 实施内容与产出

<业务目的、具体改动和交付产出；按需说明关键业务规则及异常。>

## 依赖

<实际任务编号及所需产出；无依赖写“无”。>

## 完成标准

- <正常业务结果。>
- <相关关键异常或兼容结果。>
```

## 拆分任务的主任务骨架

需要拆分多个实施任务的业务工作包使用以下主任务骨架，标题必须填写已核对的主任务编号。填写时按涉及的端或业务环节组织业务说明，不强制每个需求分端；端或业务环节标题仅组织说明，不形成新的父任务。按需保留截图和必要边界，子任务一览只列实际拆出的任务，并将下方子任务段替换为对应写法。

```markdown
# <主任务编号> <任务名称>

## 任务概述

<用简短文字说明为谁解决什么问题，以及整体要做什么；不复述编号、任务数量、清单用途或通用管理流程。>

## 业务说明

### <相关端或业务环节>

<必要业务规则、目标效果和本次改动。>

## 整体完成标准

- <完整流程的可检查结果。>
- <与本次改动直接相关的关键异常结果。>

## 子任务一览

| 编号 | 具体名称 | 类型 | 责任角色 |
| --- | --- | --- | --- |
| <父任务编号-01> | <具体任务名> | <设计/验证或开发等实际类型> | <责任角色> |

## 具体子任务

<选用下方写法，逐项填写。>
```

## 子任务写法

以下骨架不固定任务数量和流水号。每项只使用一种主要写法；子任务自身的业务信息要完整，不同时叠加内容相同的“任务目标”“业务行为表”和“开发描述”。

### 核查任务

围绕真实未知项写问题及需要产出的结论，不强制提供页面参考图。明确核查起点；不知道的字段、路径和行为就是核查内容，不编造名称填空。

```markdown
### <父任务编号-流水号> <核查对象及具体目标>

**任务信息**

- 编号：<子任务编号>；父任务：<主任务编号>。
- 类型：设计/验证；责任角色：<角色>。

**核查内容与产出**

<核查对象、必要业务含义和已有的具体入口。>

1. <需要查明的链路、数据或能力。>
2. <需要确定的规则映射或技术行为。>
3. <整理所需结论、接口契约或样例，说明供哪些实际任务使用。>

**依赖**

<具体任务编号及所需产出；无依赖写“无”。>

**完成标准**

- <核查结论能够明确回答的问题。>
- <下游实施所需且可核对的契约或样例。>
```

### 后端任务

集中描述接口及数据需要实现的业务行为，不复制页面布局。接口已有明确结论时直接使用；依赖核查时引用实际核查任务。

```markdown
### <父任务编号-流水号> <具体后端任务名称>

**任务信息**

- 编号：<子任务编号>；父任务：<主任务编号>。
- 类型：开发；责任角色：后端。

**开发内容**

<本任务负责的业务能力及数据含义。>

1. <接口或数据处理的具体改动。>
2. <本次涉及的默认值、归属、一致性或兼容要求。>
3. <与本次改动直接相关的失败行为。>

<交付接口或其他实际产出；需要时提供联调样例。>

**依赖**

- 开发前置：<具体任务及产出。>
- 接口联调：<实际需要的其他接口或任务产出。>

**完成标准**

- <正常业务结果。>
- <关键异常或兼容结果。>
```

### 页面任务

把具体页面修改与开发描述合并。简单开关或文案调整只写必要条目；不用为未变化的导航、键盘、按钮反馈等单独列设计表。相关截图直接放在本任务内。

```markdown
### <父任务编号-流水号> <具体页面任务名称>

**任务信息**

- 编号：<子任务编号>；父任务：<主任务编号>。
- 类型：开发；责任角色：<Web、POS开发或其他实际角色>。

**开发内容与页面说明**

在<页面入口与区域>，<增加或修改什么控件、列或文案>，<有图时引用具体图号及图名>。

- <准确名称或文案、业务含义和位置。>
- <与本次改动有关的默认值、显示条件或关键状态。>
- <需要接入的接口行为；通用样式与交互沿用现有实现。>

**依赖**

- 开发前置：<具体任务及产出。>
- 接口联调：<具体任务及可用接口。>

**完成标准**

- <页面改动正确，正常操作结果可检查。>
- <本次关键状态或异常结果正确。>
```

阶段、就绪状态、整体联调条件、特殊限制仅按实际需要补充；无依赖时将依赖条目替换为“无”，不保留空占位。页面骨架有截图时，在页面说明之后嵌入编号图片及图注。

## 生成后检查

- 任务概述只包含业务说明；删除重复介绍主编号、子任务数量及归属、清单权威性、评估排期和通用评审验收流程的段落。编号及归属检查在生成时执行，不转写为任务正文中的自我说明。
- 独立业务方案有自己的主任务编号、业务范围和整体完成标准，不能用无编号的文档标题代替主任务。
- 单任务直接使用主编号，必要实施字段齐全，不存在仅套一层的子任务；统计时只计一项。本次规则不自动批量转换已有任务，已有任务仅在明确要求时调整，并同步旧编号映射与入口。
- 拆分任务中，本主任务下所有子任务的编号前缀及“父任务”字段与主编号一致，核查、后端、POS、Web等角色差异没有造成跨父包分挂；外部既有任务只通过依赖引用。
- 仅移动文档时保留归属；明确调整为独立工作包时完成编号迁移。迁移前后活动任务不重复计数，旧编号有映射，受影响引用及工作包汇总已同步。
- 批次归属符合用户安排；排除某批次的工作包及其子任务没有成为该批次的交付内容或开发前置。
- 单独阅读每个子任务，能知道改哪里、做什么、依赖什么、怎样算完成；不存在必须回主任务才能找到的基础要求。
- 核查任务产出对应下游真正需要的输入；没有虚构资料、接口或技术结论。
- 编号唯一、依赖真实，开发前置无环；三端共同验收条件不变成相互等待的开发前置。
- 页面说明只覆盖改动，截图编号一致、就地可读；没有删掉关键业务规则，也没有把小改动写成通用交互手册。
- 清除填写提示、空占位、工时和完成证据字段、自动拆出的评审验收任务，以及重复说明。
- 文档使用 UTF-8 无 BOM、LF 换行；检查表格列数、相对链接和图片路径。

生成规则按以下场景核对，不在生成的任务正文中复制这些示例：

| 场景 | 应生成的结构或处理结果 |
| --- | --- |
| 独立后端优化只有一个实施目标 | 直接使用主编号编写实施内容、责任角色、依赖及完成标准，不创建子任务 |
| 在已有功能中仅增加开关，接口已具备 | 沿用已有父包，形成简短页面子任务，不机械新建工作包 |
| 将跨端配置下发作为一个独立业务方案，且链路未知 | 一个主编号；核查及各端实施任务统一使用该编号前缀，以责任角色区分。核查产出是开发前置，可用接口是联调条件 |
| 将订单单号本地生成方案作为独立任务，排除当前批次 | 一个有编号的业务主任务；兼容核查、本地序列及销售接入均为其子任务。既有成交保存和上传任务作为跨包依赖 |
| 仅将现有任务移到单独文件展示 | 保留原父子归属及编号，不因换文件新增工作包或重复计数 |
| 将已分挂多个父包的任务改为一个独立工作包 | 分配统一主编号及子编号，旧编号保留迁移映射，同步依赖和受影响汇总；不同时保留两套活动任务 |
