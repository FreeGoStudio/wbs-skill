# 已有规划维护

仅在修改已有任务或用户要求相关维护时阅读对应章节。遵从项目现有约定；以下预算粒度来自原规划实践，其他项目没有采用时不强加。新任务仍不预填估算。

## 归属、迁移和文档

- 保留稳定编号，取消和迁移编号不复用。仅移动文档或调整批次不改变父子归属；用户明确要求独立工作包时统一主编号、子编号与父任务字段，保留旧编号跳转和迁移映射，同步依赖、导航及受影响汇总。
- 当前完整任务字段与简版、批次视图同步维护；原始答复保留适用状态，不将候选方案、已取消任务或原始提问当作当前决定。
- 删除过程记录前，将独有且仍有效的结论并入当前规则；未决冲突明确列出，不自行裁定。
- 历史使用 Git 追溯，直接维护当前文件，不新增带日期或版本号的副本、修改前快照或单独差异记录。
- 按项目现有目录保存文件，新增文件补导航，移动文件同步相对链接和图片路径。外部资料保留真实来源；无法访问时报告，不伪造验证结果。
- 被取消或后移任务不得仍作为本期开发前置；产品任务迁出后保留真实跨文档依赖。变更后检查编号、依赖无环、父包覆盖、统计口径及受影响测试和里程碑，不批量调整无关记录。

## 已有预算与资源维护
以下仅适用于已有预算的维护或用户明确要求的评估记录，不要求新任务生成时填工时、拆评审测试或统计会议投入。已有评估中采用的粒度为通常2～8小时；超过8小时至16小时记录拆分例外，超过16小时需继续拆分。不从这些阈值反推新任务工时。

- 小时指人工投入，实施者的实现、自测和正常修改计在实施任务中；已有评审、独立测试、组织协调任务按各自投入计时，不据此为新任务新增独立任务。同一投入只计一次。
- 评审任务只计评审人时间；评审后的正常修改已计实施任务，超出原估算则更新剩余投入。独立测试T类工作不重复计算开发自测。
- 会议参与者各自实际投入分别计时。已有多角色投入按角色核算，不只给会议一个总时长代替多人投入。
- 接口、设备、环境、评审排队及审批等待单列日历条件，不算人工工时；8小时任务不等于一个日历日必定完成。
- 从实施任务向工作包及角色汇总，1人日=8小时；父包汇总不再额外计费。审查工时归实际审查角色，不按父包名推定执行人。
- 与 Git 中的历史估算逐包对照，标明范围变化、拆分发现的遗漏、复用前提及不确定性。不为匹配旧预算压低子任务估算；不从删除任务数直接推导周期缩短。
- 用角色负荷、实际工作日历和有向依赖检查里程碑。跨包依赖完成后才可集成，工作量下界不能当成交付承诺。支持角色、外部等待及风险预留单列。

## 已有产品任务与实施任务维护
以下维护已存在或用户明确要求单列的产品任务。新生成任务默认由产品按整体完成标准验收，不为常规产品验收新增独立任务，也不强制引用不存在的产品文档或版本。

- 已单列的产品负责人工作维护在产品任务清单中，区分“规划前置”和“测试、验收阶段配合”。保留唯一任务编号及父工作包归属，不与实施清单重复计时。
- 范围、业务规则、金额样例及业务验收口径属于相关实施任务定稿的前置输入；引用具体产品任务编号、产出文档及版本。未齐时仅作条件估算，不声明可执行，不重新索取已确认决定。
- 测试样本业务评审和试点签收依赖对应测试或试点产出，按原阶段安排；不得机械前移，也不要求所有产品事项完成才启动所有开发。技术未知由对应核查任务查明。
- 迁出产品任务保留原编号锚点、历史映射及跳转入口，实施清单以“产品前置”或“产品阶段配合”明确引用真实任务，保留原阻塞关系。
- 工作包分别汇总实施投入、产品投入与项目合计；角色负荷、排期和依赖检查覆盖两份清单。产品工时从实施预算分离但不得从项目总投入删除，等待不计人工。
- 核对两份清单活动编号唯一、依赖有效且无环；历史映射和迁移入口不计为活动任务，文档分离不表示任务实施或业务验收完成。

## 规划阶段不分配个人
- 未进入人员分配阶段时，只标责任端/角色，不使用POS A、POS B等个人占位分组，也不预先指定任务由哪位开发执行；POS工作统一归POS开发。
- 角色投入按全部相关任务汇总；人数仅作容量假设，不能等同已到岗或已完成任务分配。个人任务和负荷在分配阶段再建立。
- 已有独立评审任务维护时单独计时，执行时评审人与对应实施者应分离；相同角色不代表可以自审。历史固定分工的排期不得冒充合并角色后的已确认排期。
